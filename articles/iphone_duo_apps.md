個人で出している iOS アプリを、iPhone Duo に合わせて順番に直していきました。対象は Intento（IntentTodo）、GRAPHICA、Graphica Playground、Toreta、Programming Quiz、チェケラ、FFMultiplier の 7 本と、Duo のために新しく作った月屏風の計 8 本です。

やってみると、直したことはアプリごとにばらばらに見えて、実は同じいくつかの論点に集まっていました。この記事では、アプリ別ではなく論点別に「何を前提にして、どう組み直したか」をまとめます。

## 実機は持っていないけれど、触ったことで変わった

先に書いておくと、Duo の実機は買っていません。確認はシミュレータと TestFlight で、記事中のスクショも撮影スクリプトで撮ったものです。

ただ、公式のワークショップで実機を触る機会がありました。そこで、**折り目は画面の上ではただの線でも、手に持つと確かにそこにある**ことが分かりました。カードや文字が折り目をまたぐと、思った以上に読みにくい。シミュレータだけを見ていたら、折り目を避ける工夫は「余裕があればやる」程度で終わっていたと思います。実機を持っていなくても、この一度の体験が、後半の章のこだわりにつながりました。

## 閉じると背が低くなり、バーが右へ移る

閉じた Duo の外側の画面は 466×678pt です。普通の iPhone と比べると、幅はあまり変わらず、**背がぐっと低い**形になります。そのぶん、ツールバーやタブバーは画面の下や上ではなく、**右端の縦の列**に移ります。ステータスバーも同じ列に入り、右側に 84pt ほどの safe area ができます。

![閉じた Duo の Intento](/images/iphone_duo_apps/intento-closed-list.jpg =300x)
*閉じた Duo。ツールバーの項目とステータスバーが右の列に並ぶ*

つまり閉じた画面では、**縦が足りず、横も右の列に取られる**。最初に崩れたのは、この 2 つを前提にしていなかった箇所でした。

- **Programming Quiz**: クイズと結果の画面が縦に入りきらなくなりました。入りきらないときだけスクロールに逃がすようにしました。上にバーが無くなって上の safe area が 0 になる場面でも、閉じるボタンが画面の端に付かないようにしています
- **FFMultiplier**: チュートリアルを固定サイズで組んでいたので、縦に収まりませんでした。固定サイズをやめました
- **チェケラ**: 右の列のぶん横幅が減り、録音パネルの REC / STOP / PLAY / SAVE の文字が単語の途中で折り返しました。1 行に収まらないときは、大きいアイコンだけのボタンに切り替えます

![閉じた Duo のチェケラ録音パネル](/images/iphone_duo_apps/checkitout-closed-record.jpg =300x)

![閉じた Duo の Programming Quiz](/images/iphone_duo_apps/quiz-closed-question.jpg =300x)

どれも Duo 専用の分岐ではなく、「縦が足りないとき」「横が足りないとき」にどう縮むかを決めただけです。なので横向きの iPhone や Split View でも同じように効きます。

## ツールバーは「横に並ぶ」前提で整理する

バーが右の縦の列に移ると、項目は上から下へ 1 列に並びます。並べられる数は少なく、入りきらない項目はメニュー（⋯）へ回ります。アイコンだけだと何のボタンか分かりにくい、という問題もあります。

なので、**バーの項目は横の列に移る前提で、最初から整理しておく**ことにしました。Tech Talk「Raise the bar with iPhone Duo」の指針と照らし合わせて、Intento・GRAPHICA・Playground・Toreta・FFMultiplier で次の 4 つをそろえています。

| やったこと | 中身 |
|---|---|
| タイトルを持たせる | 画像だけのボタンを `Label` にする。見た目は `.labelStyle(.iconOnly)` で同じ |
| role を付ける | 閉じる = `.close`、キャンセル = `.cancel`、保存・追加 = `.confirm`、全消去 = `.destructive` |
| あふれる順を決める | `visibilityPriority` で、最後まで残す項目と先にメニューへ送る項目を決める |
| 自前の ⋯ をやめる | 自作のメニューを `ToolbarOverflowMenu` に入れる |

![閉じた Duo の Graphica Playground](/images/iphone_duo_apps/playground-closed-editor.jpg =300x)

一番効いたのは 1 つ目でした。Intento では、開いた Duo で「追加ボタンが無くなる」という報告があり、調べると**アイコンだけのボタンはメニューに載らず、畳まれる代わりに消えていました**。タイトルの無い項目はメニューの行を描けないので、捨てられます。`accessibilityLabel` を付けていても、この穴は埋まりません。自分では見つけられず、「メニューにフィルタだけ残って追加が消える」という使う側の観察が決め手でした。

あふれる順は、アプリごとに「この画面で何をしに来たか」で決めました。Playground は Parameters / Export / Favorites を最後まで残し、設定と Pro を先に送ります。FFMultiplier は全削除と共有を先に送ります。項目そのものを減らした画面もあります。Intento のリスト列は、`.bottomBar` や `.topBarPinnedTrailing`、`visibilityPriority(.high)` も試しましたが、この幅のバーが持てるのはシステムのサイドバー切替を含めて 2〜3 個で、減らす以外に手がありませんでした。

role を付けたことで、普通の iPhone でも閉じるボタンの × が右上から左上へ移りました。Duo のための整理が、ほかの端末の見た目も少し変えます。

## 左右で違う safe area は contentMargins に任せる

右の列があるので、Duo は safe area が左右で違います。中身に `padding` を直接付けていると、片側だけ詰まって見えます。

![閉じた Duo の Toreta コレクション](/images/iphone_duo_apps/toreta-closed-collection.jpg =300x)

Toreta・GRAPHICA・Playground では、スクロールの外周の余白を `padding` から `contentMargins` に寄せました。余白の量だけ伝えて、safe area の内側でそろえるのはシステムに任せる形です。

横スクロールの列は扱いを分けました。Playground のヒントのチップの列は、右の列の下まで流して、タブの下に潜らせています。見出しや入力欄は safe area の内側に置いたままです。Toreta のチップの列も、余白を打ち消して端まで流しています。

![開いた Duo の Toreta コレクション](/images/iphone_duo_apps/toreta-open-collection.jpg)

## 画面を分けるかは size class と縦横で決める

開いた Duo は 951×669pt で、横は regular になります。iPad に近い扱いです。ここで「左右に分けるか、1 カラムに積むか」をどう決めるかで、2 回つまずきました。

1 回目は、ピクセル幅の閾値で決めていたことです。GRAPHICA では最初、幅 600pt 以上なら広い画面として扱っていました。でも Duo の開いた幅や iPad の 2/3 幅のように、閾値の前後に来る形は増え続けます。これは size class に切り替えました。

2 回目は、**size class だけで決めたら崩れた**ことです。Playground のレッスン画面は、広い画面では「説明と絵」を左、「コードとヒント」を右に分けます。ところが、開いた Duo や iPad を**縦に持つと、regular なのに縦長**です。親の画面は「regular かつ横長」で判定して 1 本のスクロールに積んでいたのに、その中の子ビューが size class だけを見て絵とコードを左右に並べていました。結果、**1 本のスクロールの中に左右の列ができる**中途半端な画面になりました。

![開いた Duo の Playground レッスン](/images/iphone_duo_apps/playground-open-lesson.jpg)
*横に持ったとき（regular かつ横長）だけ左右に分ける*

ここから、次のルールにしました。

- 構成の切り替えは `horizontalSizeClass` を起点にし、ピクセル幅の閾値は使わない
- regular でも、左右に分けるのは**横長のときだけ**。縦横は safe area を足し戻したウィンドウ全体の寸法で見る
- 判定は 1 か所に置き、子には結果（Bool）だけを渡す。子が size class を読み直すと、親と条件がずれる
- 幅で決めてよいのは、格子の列数のような**中身の詰め方**だけ

## 折り目を避けてレイアウトする

ワークショップで触って一番気になった折り目です。iOS 27.1 では、折り目の位置を `GeometryProxy.reservedRegions(kind: .division)` で取れます。これを使って、**カードや文字が折り目をまたがない**ように組みました。

![開いた Duo の Playground 学ぶ](/images/iphone_duo_apps/playground-open-learn.jpg)
*列の間の隙間が、ちょうど折り目に来る*

- **格子は列の間を折り目にする**: Playground の「学ぶ」の一覧と、GRAPHICA のギャラリー・マイページの格子は、開いたときに 2 列にします。縦の折り目があれば、その幅をそのまま列の間の隙間にします。`LazyVGrid` / `GridItem` には折り目を避ける指定が無いので、自前の `Layout` で組みました
- **分かれ目は割合で持つ**: 折り目の値は、配置の 1 フレーム後にしか届きません。最初は列の幅を絶対値で持っていたら、開閉のたびに左の列だけガタつきました。分かれ目を幅に対する割合で持つと、幅のアニメーションに両方の列が追従し、遅れて届く補正もアニメーションでならせます
- **はみ出すものは止める・飛ばす**: Playground のトップのガラスのカードは折り目の手前で止めます。GRAPHICA のマイページの SNS のチップは、折り目の範囲を飛ばして並べます

![開いた Duo の GRAPHICA ギャラリー](/images/iphone_duo_apps/graphica-open-gallery.jpg)

画面を 2 つに分ける画面は、iOS 27.1 の `ArrangementView`（split スタイル）に任せました。表示する部分と操作する部分を渡すと、横長なら左右、縦なら上下に分け、**開いた Duo では分かれ目が折り目に合います**。折り目を避けるために位置を計算したというより、「見る側」と「触る側」を正しく分けておいたら、結果として折り目を避けてくれた、という感覚です。

- **Programming Quiz**: 問題と選択肢を分けました。「次の問題へ」ボタンの場所は常に確保して、答えても高さが変わらないようにしています
- **FFMultiplier**: ゲーム画面の数字の表示と、入力のボタンを分けました
- **チェケラ**: 半開きのときは、パッドを折り目の片側に、ロゴ・リスト・操作をもう片側に置きます。形が変わるときは `matchedGeometryEffect` で部品がつながって動きます
- **GRAPHICA / Playground**: 作品の詳細と Create、レッスンを左右に分けました

![開いた Duo の Programming Quiz](/images/iphone_duo_apps/quiz-open-question.jpg)

## ヒンジの角度そのものを体験にする（月屏風）

7 本を直したあと、折り目とヒンジを避けるのではなく**主役にする**ものを 1 本作りました。月屏風は、ヒンジの角度を月の満ち欠けに対応させたアプリです。0° が新月、180° が満月で、二曲の屏風を開くように月が満ちていきます。

![開いた Duo の月屏風](/images/iphone_duo_apps/tsukibyobu-open.jpg)

折り目は屏風の二扇のつなぎ目として描きます。平らに近づくほど、二扇の間の余白を詰めます。

![折り目の余白の比較](/images/iphone_duo_apps/tsukibyobu-gap-compare.jpg)

描画は、角度で変わらない層と角度で変わる層に分けました。ヒンジを動かしている間は軽い層だけを描き直すので、1 フレーム約 2ms で済んでいます。Duo 以外の端末ではスライダーで角度を変えます。

### 縦長の画面には床を敷いて映り込ませる

屏風は横に広い絵なので、普通の iPhone の縦長の画面だと上下が余ります。最初は屏風を画面いっぱいに描き、主役の梅を下の操作の帯より上に置くなど、絵の側で操作を避けていました。場所や季節ごとに配置を調整する必要があり、無理が出ていました。

そこで、**屏風を高さの 75% に縮めて上に立て、下の 25% に黒漆の床を敷きました**。床には屏風が上下反転して映り込みます。映りは足元がいちばん濃く、離れるほど薄く、ぼかしを強くしています。舞う花びらや雪も映ります。床はボタンの置き場にもなったので、絵の側で操作を避ける必要がほぼ無くなりました。

![縦長の画面の月屏風と黒漆の床](/images/iphone_duo_apps/tsukibyobu-portrait-floor.jpg)

Duo を横に持つと、扇が上下に並びます。このときは上の扇に屏風を立て、下の扇を床にしています。**閉じ気味ほど映りが縦に縮んで濃く、平らに開くほど伸びて薄く**なるので、ヒンジの角度で床の見え方も変わります。

![横持ちの Duo と黒漆の床](/images/iphone_duo_apps/tsukibyobu-landscape-floor.jpg =400x)
